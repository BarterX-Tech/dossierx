A system record for software built with coding agents.

Understanding the software
we build with agents

When you build with coding agents, a working feature can arrive before you have a clear account of how it works. The agent can explain the code, but that explanation lives in a conversation. A few changes later, it may describe a system that no longer exists.

You are still responsible for the product. You need to know what it does, which decisions you have accepted, and what needs another look when something changes.

DossierX is a system record for that work. It gives you and your coding agents a shared place to maintain reviewable statements about the software, alongside their sources and your review decisions.

Something you can review

A statement might say: “A failed payment is retried three times before it goes to manual review.” It can link to the relevant code and to another statement explaining which failures qualify for a retry.

DossierX calls these statements claims. Keeping them small gives you something specific to question. You can open a claim in the viewer, inspect its sources and relationships, leave a comment, and ask the agent to investigate.

The agent writes and updates the record. You review its account of the system and approve the claims you are willing to stand behind. DossierX records those approvals and checks whether locked claims still match what was approved.

The claims and review records live in your project’s repository. They remain available when a conversation ends or you change agents.

When the software changes

Suppose you decide to increase the retry limit from three to five. The existing claim gives the agent a decision to revisit. The linked code and related claims give it places to investigate: does the new limit apply to every eligible failure, and what else depends on the old rule?

You can review the proposed statement and the evidence for the change. Once accepted, the revised record gives the next task a place to begin.

DossierX can report changes to approved claims and recorded dependencies. People and agents still need to investigate what those changes mean for the software. An approval records a decision; code inspection, tests, and real use are how you check whether the implementation supports it.

Start with one part of the product

DossierX works alongside your coding agent. Ask it to document one area you need to understand, then read and question the result. For a new feature, you can begin by recording the intended behaviour before implementation starts.

The useful starting point is a part of the product where a misunderstanding would matter. You can expand the record as you learn which statements are worth maintaining.

What we are working toward

As coding agents take on more of the work of building software, people will be responsible for systems they did not write line by line. They will still need to decide how those systems should behave, understand the consequences of a change, and answer for the result.

Our vision for DossierX is to make that responsibility practical. The person shaping a product should be able to examine its behaviour, trace the reasoning and evidence behind it, and question decisions without having to reconstruct the whole system from code and old conversations.

We want that understanding to accumulate as the software grows. A decision reviewed today should give tomorrow’s work a foundation. When its assumptions change, it should be possible to see what needs another look.

DossierX starts with a system record. The larger ambition is to help people remain thoughtful authors of their software as agents do more of the implementation.
