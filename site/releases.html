Releases

What has shipped.

Every tagged release, newest first. CHANGELOG.md has the full account.

v0.7.3 2026-08-29

Individual claims fold without losing their placeLatest

Every claim in the generated System Record viewer can now collapse from its title row. The title, status, and comment control stay visible; direct links reopen the target, print retains the complete record, and the disclosure arrow stays at the far right at every viewport. No claim schema, command, lint, or lock behaviour changes in this release.

v0.7.2 2026-08-29

Claim prose uses the full card width

Generated System Record viewers no longer constrain claim bodies to a narrow text column inside a wide card. Long claims now use the available content width on desktop and continue to fit the card on smaller screens. No claim schema, command, lint, or lock behaviour changes in this release.

v0.7.1 2026-08-28

The system record becomes a reading workspace

The generated viewer gains grouped navigation, a resizable drawer, facet contents, clearer claim cards, vertical evidence records, and a graph that opens with every claim visible. The website gallery now shows the shipped design with synthetic public claims instead of older customer-derived captures. No claim schema, command, lint, or lock behaviour changes in this release.

v0.7.0 2026-08-23

A claim can carry its evidence, and a feature can be read as one thing

Claims gain sources, so the evidence behind a sentence lives in the claim and is signed when the claim locks. They gain tracks, so a feature spread across many modules can be read as one document and asked whether it is finished. The release gate pipeline is gone: DossierX is alpha and releases are cut by a maintainer. One behaviour change to check for in your scripts: dossierx check <anything> now exits 1 instead of silently discarding the argument.

v0.6.0 2026-08-20

The guides match the engine, and every install prints the tag

Four shipped skill guides described procedures that do not work, and the skills are embedded in the binary. Re-run dossierx skills export after upgrading, or your agents keep following the old ones. No command, flag, error code, lint rule or gate behaves differently.

v0.5.1 2026-08-10

The release pipeline itself, gated end to end

Every client-facing surface is declared and read by its own agent at release time. Publishing became a driver that refuses an ungated or half-published tag instead of a sequence somebody types. Re-run dossierx skills export after upgrading.

v0.5.0 2026-08-07

A claims graph in the viewer

A reviewer can see and navigate the dependency structure between claims instead of inferring it.

v0.4.1 2026-08-04

raw_html becomes an attachment, and the edges footer folds away

v0.4.0 2026-08-03

Migration removed, and governed_by becomes a drift edge

The migrate command is gone with no replacement.

v0.3.1 2026-07-30

A documentation-grade renderer

v0.3.0 2026-07-28

Agent-first restructure, two surfaces and one gate

The machine contract became the spine. JSON by default, one envelope per invocation, stable error codes, and a dry run on everything that writes. The command surface shrank and got more capable.

v0.2.0 2026-07-26

Comments on claims, so a human can argue before locking

The reviewer's half of the loop arrives. A claim with an open thread cannot lock.

v0.1.2 2026-07-25

Consolidated audit-fix release

v0.1.1 2026-07-24

Steps number and text alignment fix

v0.1.0 2026-07-23

Renamed docs to dossierx

Breaking, with no migration. The on-disk lock and flag stores are renamed, so an existing project's stores are not found after upgrading past this release.

v0.0.3 2026-07-22

Viewer freshness cue

v0.0.2 2026-07-22

Cross-platform hardening

Concurrent locking against the same claims directory could fail on Windows with a transient sharing error. Both paths now retry.
