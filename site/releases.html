Releases

What has shipped.

Every tagged release, newest first. CHANGELOG.md has the full account.

v0.7.9 2026-09-07

Bounded readiness, and a clearer front doorLatest

Readiness evaluation now keeps one deterministic witness for each independent obstacle instead of enumerating every dependency route. Dense policy-v1 graphs stay bounded while missing, retired, unreadable, cyclic, and independently clearable causes remain visible. The project also gains maintainer review guidance for graph changes and a new memo-style landing page that states the product's purpose before its mechanics.

v0.7.8 2026-09-06

Reviewed local approvals, live dependency readiness

Lock policy v1 makes a reviewed local approval distinct from an integrated-ready claim. A readable draft dependency can remain visible as an unapproved condition; retired, unreadable, missing, cyclic, and doctrine-gated required dependencies refuse a new approval. Every lock starts with a reviewable preview and its request-bound proposal token. Existing projects adopt this policy explicitly with claim migrate-lock-policy. The viewer now shows local approval, dependency conditions, and review paths on the claim card, while the build/ artifact layout and Build order diagram introduced in v0.7.7 remain in use. Locked diagrams now show an explicit Claim not found status when a catalog claim is gone, and generated viewers keep their runtime JavaScript and live fragment behavior stable while preserving authored whitespace. CI and render comparisons share one validated immediate prior-release resolver.

v0.7.7 2026-09-04

Everything generated moves under build/, and the build order becomes a diagram

Every file the engine writes now lives under one directory, build/ (configurable as build_dir), one subdirectory per kind: the lock, comment and flag ledgers, the build-order and code-link artifacts, the catalog and the viewer. Nothing is written to the project root any more. This is a breaking change for every existing project: until the seven legacy root files are moved, every command, including dossierx check --validate and --staged, is refused with error.code: layout_legacy and prints the exact mkdir -p / git mv block to paste. Run that block once and commit it; signatures hash bytes, not paths, so nothing is re-locked. The viewer's per-module Build Order sub-tab and its flat per-claim list are replaced by a top-level Build order tab that draws the locked sequence as a six-phase mermaid diagram, and dossierx build-order show --format mermaid prints the same diagram for a PR. A viewer for a project with a locked build order now carries the vendored renderer and grows by about 3.6 MB. Locking commands now require git on PATH inside a work tree and refuse when a ledger path is gitignored (store_gitignored). Re-run dossierx skills export after upgrading so your agents learn the new layout.

v0.7.6 2026-09-02

Viewer custom themes

The generated viewer can now be restyled with a project's own colours and fonts through viewer.theme: a built-in claude preset, an optional theme file a project can layer on top of it, per-colour-scheme (light/dark) overrides, and the project's own local font files inlined into the page. dossierx theme list and dossierx theme export discover and start from a preset. Also fixed: a hairline seam that split every line of a multi-line fenced code block into its own box, fenced code blocks in step, comment, and list-item bodies rendering as unstyled inline-code pills instead of code blocks, the viewer's OS dark-mode support for native form controls and other browser-drawn surfaces, and printing so it always uses the light palette regardless of the reader's system theme or a project's dark-mode overrides. Existing projects should run dossierx check to regenerate their viewer and dossierx skills export to refresh the embedded agent guide. No claim schema, command, lint, or lock behaviour changes in this release.

v0.7.5 2026-08-30

The viewer makes room for the record

The desktop module navigation and active-facet table of contents can collapse into recovery rails, and one facet control can fold or restore every claim. Live lint and approval-record issues now sit inside the affected facet, use the viewer's own visual system, and stay out of unrelated modules and facets. No claim schema, command, lint, or lock behaviour changes in this release.

v0.7.4 2026-08-29

Navigation groups stay where readers leave them

Modules and Tracks now remain collapsed when a reader closes them, including when the group contains the selected item. Selecting a new navigation item still opens its group, and large records can reach Tracks without scrolling through every module. No claim schema, command, lint, or lock behaviour changes in this release.

v0.7.3 2026-08-29

Individual claims fold without losing their place

Every claim in the generated System Record viewer can now collapse from its title row. The title, status, and comment control stay visible; direct links reopen the target, print retains the complete record, and the disclosure arrow stays at the far right at every viewport. No claim schema, command, lint, or lock behaviour changes in this release.

v0.7.2 2026-08-29

Claim prose uses the full card width

Generated System Record viewers no longer constrain claim bodies to a narrow text column inside a wide card. Long claims now use the available content width on desktop and continue to fit the card on smaller screens. No claim schema, command, lint, or lock behaviour changes in this release.

v0.7.1 2026-08-28

The system record becomes a reading workspace

The generated viewer gains grouped navigation, a resizable drawer, facet contents, clearer claim cards, vertical evidence records, and a graph that opens with every claim visible. The website gallery now shows the shipped design with synthetic public claims instead of older customer-derived captures. No claim schema, command, lint, or lock behaviour changes in this release.

v0.7.0 2026-08-23

A claim can carry its evidence, and a feature can be read as one thing

Claims gain sources, so the evidence behind a sentence lives in the claim and is signed when the claim locks. They gain tracks, so a feature spread across many modules can be read as one document and asked whether it is finished. The release gate pipeline is gone: DossierX is alpha and releases are cut by a maintainer. One behaviour change to check for in your scripts: dossierx check <anything> now exits 1 instead of silently discarding the argument.

v0.6.0 2026-08-20

The guides match the engine, and every install prints the tag

Four shipped skill guides described procedures that do not work, and the skills are embedded in the binary. Re-run dossierx skills export after upgrading, or your agents keep following the old ones. No command, flag, error code, lint rule or gate behaves differently.

v0.5.1 2026-08-10

The release pipeline itself, gated end to end

Every client-facing surface is declared and read by its own agent at release time. Publishing became a driver that refuses an ungated or half-published tag instead of a sequence somebody types. Re-run dossierx skills export after upgrading.
