The system record

One plain-English list of how your software works.

Each rule points to the code behind it and keeps a record of who approved it.

What stays with each rule

Code
The file or test where the rule is implemented.
Links
The other rules this one depends on.
Questions
Review notes stay beside the rule.
Approval
A record of who accepted it and why.

How the work moves

You maintain the rules. Agents work from them.

When the code and a covered rule may disagree, the rule comes back to you.

  1. 01Agent

    Draft

    Turn the code or your request into short rules.

    →
  2. 02Human

    Review

    Read the rules in plain English and question them.

    →
  3. 03Human

    Approve

    Accept the rules that describe the product correctly.

    →
  4. 04Agent

    Build

    Use the approved rules while changing the code.

    →
  5. 05System

    Check

    Report covered changes that may have made a rule stale.

    →
  6. 06Human

    Decide again

    Update the rule or send the code back for another change.

What this record cannot promise

DossierX cannot prove that every rule matches every line of code. It keeps reviewed rules linked to their sources and reports covered changes that may have made them stale. Tests and code review still matter.
