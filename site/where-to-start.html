Where to start

Do not explain the whole codebase.

Start with one feature that is expensive to misunderstand.

01

Existing app

Find out what the app already does

Start with one part of the product that is hard to change without breaking something.

  1. Choose one feature or workflow.
  2. Ask an agent to draft its rules from the code and docs.
  3. Review those rules in plain English.
  4. Approve the useful rules and keep them with the code.

The next agent starts with the rules instead of researching the feature again.

02

New app

Write the rules before the agent writes the code

Decide how the product should behave while the implementation is still easy to change.

  1. Write each important behavior as a short rule.
  2. Add the decision or requirement behind it.
  3. Review and approve the rule.
  4. Give it to the agent and link the finished code back to it.

The product decisions survive after the coding chat is gone.

03

Next agent

Continue the work without starting from zero

Give the next agent the rules for the task instead of the whole project history.

  1. Load the rules for the feature.
  2. Include their sources and connected rules.
  3. Keep open questions with the rule they affect.
  4. Review only the rules touched by the change.

The handoff is smaller and easier for you to check.
