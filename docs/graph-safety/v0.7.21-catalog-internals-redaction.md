# Graph-safety evidence: catalog.json internals redaction (v0.7.21)

Scope: the catalog graph projection only (`internal/catalog`, `Document` and the
`EncodeJSONBounded` capacity preflight). Readiness computation, locking, review
propagation, the viewer and `serve` are not changed by this item.

- Candidate: commit `64f6fd5` (fix(catalog): never emit an internals id...) on
  branch `fix-catalog`; measurements re-run on the branch tree at `cd75f51`, whose
  later commits do not touch `internal/catalog` or `internal/readiness`.
- Comparison baseline: `0f758b2` (`origin/release/v0.7.21` at the start of this
  fix), `internal/catalog/catalog.go` swapped in with every other file unchanged.
- Environment: go1.26.0 linux/amd64, 4 CPUs, shared sandbox with other agents
  running tests in parallel (timings are noisy; bytes, counts and record identities
  are exact).

## Contract change (approved by the release coordinator, item D1)

FORMAT.md says integration output, `catalog.json` included, never includes
internals. Before: internals claims and `edges.rests_on` targets were dropped, but
`readiness` was copied verbatim, so exported entries named internals ids in
`path`, `dependency_id` (conditions, dependency_conditions, causes,
review_causes), and copied internals-authored `detail` (flag reasons, open
thread ids). `fixture-graph-demo` leaked 10 distinct internals ids (64
occurrences) and `fixture-theme-flat` leaked 1 (6 occurrences).

After:

1. Every internals id in a readiness `path` hop or `dependency_id` becomes
   `(internals)`. That string is not a valid claim id (ids are
   `module.facet.slug`, kebab case), so it can never resolve to a claim.
2. `detail` on an `own_flag` / `own_thread` cause whose owning claim (last path
   hop) is internals becomes `withheld: authored on an internals claim`. Engine
   details are fixed strings and are kept.
3. `edges.rests_on_internals_omitted` counts the rests_on targets dropped
   because they are internals (omitempty: projects without such edges are
   byte-identical).
4. The capacity preflight lower bound walks only what `Document` emits. It
   charged internals claims, internals edge targets and internals ids, so an
   unemitted byte could refuse a valid catalog (regression test
   `TestEncodeJSONBoundedDoesNotChargeOmittedInternals`, fails on baseline).

## Preserved invariants

- Readiness is still computed once by `readiness.Compute`; the catalog only
  rewrites strings in its own copy (`redactAssessment`). No traversal, cause
  determination or baseline logic was added; the input assessment is not
  mutated (slices are copied before rewriting).
- Per exported claim: `local_approved`, `dependency_ready`, `review_pending`,
  `ready`, record kinds, record counts, record order and path lengths are
  unchanged. A claim blocked only by an internals prerequisite still reports
  `dependency_ready: false` with its `dependency_unapproved` record.
- Each independent fact keeps its own record (no dedup after redaction), so the
  number of conditions/causes still counts independent obstacles.
- Membership: exported entries, `by_facet`, `by_module` are unchanged.

## Complexity

Let `R` be readiness records on one exported claim and `D` the longest witness
path. Redaction is one pass over that claim's records and hops: O(R·D) time and
one copy of the same size, i.e. linear in the bytes the baseline already
serialized. Whole corpus: O(sum of assessment sizes) = O(size of catalog.json).
Serialized size changes by at most `len("(internals)") + 2 - len(id) - 2` bytes
per redacted hop (it shrank on every measured shape) plus one small integer
field per entry with omitted edges. No bound depends on path count.

## Adversarial scale measurements

Harness: `docs/graph-safety/v0.7.21-catalog-internals-redaction-harness_test.go.txt`
(copy to `internal/catalog/zz_graphsafety_evidence_test.go`, then
`DX_EVIDENCE_OUT=<file> go test ./internal/catalog -run TestZZGraphSafetyEvidence -count=1`).
All-draft graphs (every claim carries conditions), single module, internals on
odd nodes (chains) or odd layers (dense layered DAGs, every node rests on every
node of the next layer). `readiness.Compute(claims, nil, nil)` then
`EncodeJSONBounded(cat, 64 MiB)`.

| chain-32 | 32 / 16 | 341,159 | 322,327 | 3,264 -> 0 | 512 | yes | 1.21 MB -> 1.43 MB |
| chain-64 | 64 / 32 | 2,094,311 | 1,952,199 | 23,936 -> 0 | 2,048 | yes | 7.86 MB -> 9.32 MB |

Every baseline internals-id occurrence became exactly one `(internals)` token
(redacted_tokens equals the baseline leak count). All outputs are far inside the
64 MiB catalog budget and the < 64 MB containment budget; encode time stayed
under 0.25 s for every shape (chain-128: 187 ms baseline, 216 ms candidate, one
noisy run each). Raw results:
`v0.7.21-catalog-internals-redaction-baseline-0f758b2.json` and
`v0.7.21-catalog-internals-redaction-candidate.json` beside this file.

## Consumer proof

- Write-mode `check` and the emitted file: `tests/catalog_internals_redaction_test.go`
  (`TestCatalog_ContractRestingOnInternalsNamesNoInternalsID`) builds a project
  with a contract claim resting on its module's internals claim, runs the real
  binary, and asserts on `build/catalog/catalog.json`: no internals id or
  internals flag reason anywhere in the bytes, `rests_on_internals_omitted: 1`,
  the draft-prerequisite condition kept (`dependency_ready: false`, path
  `[api, (internals)]`), and after locking and flagging the internals claim the
  inherited `own_flag` review cause kept with its detail withheld. Fails on the
  baseline for the leak.
- Committed goldens: `testdata/fixture-graph-demo` and `fixture-theme-flat`
  `build/catalog/catalog.json` regenerated by `dossierx check`; no internals id
  remains in any fixture catalog. `testdata/render-across-releases.golden.txt`
  regenerated and read.
- Viewer, `serve`, `claim show`, `claim list`: they do not call
  `Catalog.Document`; regenerating every fixture viewer produced timestamp-only
  diffs (not committed).
- `check` catalog_count now reports `Catalog.ExportedCount()` (entries actually
  in catalog.json): fixture-graph-demo prints `(21 claim(s))`, was 58.

## Verdict

PASS for this item's obligations on the identified tree: semantic assertions
(booleans, record counts, kinds, path lengths, no leak) held on chains 32/64/128
and layered dense DAGs 8/16/24x5, consumer checks ran against the real binary,
and output stayed within budget. This is not a release graph-safety PASS: the
release item in docs/RELEASING.md needs the final merge commit and the other
slices' graph changes (lock policy work) evaluated together.
