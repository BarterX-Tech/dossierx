# v0.3.1 — the renderer decisions

**Status:** shipped in `v0.3.1` (2026-07-30). This file is the durable record of what was decided and
why. The full planning document, including all 31 amendments with their evidence, is beside it in
[`v0.3.1-renderer-plan.html`](v0.3.1-renderer-plan.html) — open it in a browser.

**Read this before changing `internal/render/markdown`.** Several of the rules below look arbitrary
until you know what they are defending against, and two of them were re-derived the hard way after an
earlier attempt shipped the obvious answer and had to be reverted.

---

## Why the release happened

A claim body accepted "markdown" but rendered a small subset: paragraphs, fenced code, inline code,
links, and one level of list nesting. No bold, no italic, no headings, no tables, no images.

The failure that motivated it, and the shape most technical documentation takes:

```
1. Install it:

   ```sh
   go install ./...
   ```

2. Then run it.
```

rendered as **two separate lists** with the code block ejected between them and step 2 renumbered to 1.
Fences were extracted from the whole body *before* block scanning, so no open container could survive
one.

---

## The rules that are not obvious

### Fence recognition lives in the line scanner

There is no whole-body fence pre-pass. `Render` is a single call to `renderBlocks`, so fences are met
in document order and an open list or blockquote survives one. The opening fence's **indent** decides
its container: indented under an item it belongs to that item; at column zero it is a top-level block.

Line-anchoring is also what makes escapes work structurally rather than by special case — a line
starting with a backslash does not start with a backtick run, so `\``` cannot open a fence.

### Underscore emphasis is safe *because of* CommonMark flanking

`_` was allowed into scope only because the flanking rule makes an intraword underscore incapable of
opening or closing emphasis. That is what stops `governed_by`, `rests_on`, `claims_dir`,
`schema_version`, `build_role`, `raw_html`, `migrated_from`, `validated_at` and `depended_by` — all
everyday prose tokens in this corpus — from italicising.

**If you weaken the flanking rule, you break the corpus.** Neighbours are classified per *character*,
not per byte: a non-ASCII dash or quote is punctuation, an NBSP is whitespace. The rule is held to all
132 emphasis examples of CommonMark 0.31.2 (129 exact, 3 recorded ceilings for raw inline HTML, which
this renderer does not support).

Residual exposure is word-boundary runs that genuinely pair — `__init__` renders as bold. See the
deferred item below.

### Looseness is a property of the list, not the item

A list containing blank-line-separated content wraps **every** item's prose in `<p>`. A tight list
nested inside a loose parent stays tight. Getting this per-item instead of per-list is the classic
implementation error.

### A well-formed table is never refused

**Two earlier attempts shipped a ceiling that refused tables and both had to be reverted.** The
padding amplification is real — a header of N columns and M one-cell rows emits N×M cells from about
N+2M source bytes — but every refusal rule contradicts the spec, which says a ragged row is padded or
truncated and *remains a table*, and every ceiling is just a different place to put a cliff authors
fall off. A four-column centre-aligned table with three ragged rows was vanishing into a paragraph.

The fix was to remove padding, not to tune the ceiling: **a short row emits exactly the cells it has**,
so every emitted cell corresponds to a source cell and the amplification vector is closed at its
origin. `tableAt` answers yes or no; there is no third verdict, and there must not be one.

Consequence: a short row renders short, leaving a ragged right edge where GFM pads. That is a
deliberate divergence.

### Other table rules the spec left open

- **The delimiter row must carry a pipe of its own.** GFM is ambiguous for a single-column table, but
  `---` is unconditionally a thematic break here, so without this rule `| a |` followed by `---` would
  silently retitle an `<hr>` as a table.
- **A pipe inside a code span splits a cell**, matching GFM. So `` `a\|b` `` — escaped — is the working
  spelling for inline code containing a pipe. This is the one documented exception to "escapes never
  process inside a code span".

### Images are fail-closed by construction, not by a flag

`markdown.Render` and `RenderInline` render **no** images and cannot be told to. `RenderClaimBody` is
the only image-permitting entry point.

This shape is deliberate. There are four `Render` call sites and two of them are comment paths
(`components.go`, and `internal/serve`'s `commentToDTO` feeding `GET /api/comments`). Under an opt-in
entry point they stay correct by changing nothing. A forgotten opt-in costs a missing diagram that
review catches; a forgotten opt-out would leak the capability into reviewer-authored comment bodies,
which nobody would notice.

A `src` must resolve under its own claim's fixed `assets/` directory — extensions `.png .jpg .jpeg
.gif .webp .svg`. `ImageSrc` **refuses rather than rewrites**: an earlier revision stripped disallowed
bytes, so `assets/team photo.png` became `assets/teamphoto.png` and the route served a *different
existing file*.

### One URL gate, in `internal/urlsafe`

Every off-origin decision goes through `internal/urlsafe`, which imports nothing from this repo.

**Do not add a second copy.** Four independent implementations existed before, and the weakest of them
guarded `raw_html` — the one field DossierX renders unescaped. It recognised `//` as an authority
prefix but not `\\`, `/\` or `\/`, which browsers normalise to it, so a *reviewed, locked, allowlisted*
mockup claim could load a third-party image. Seventeen local copies were deleted rather than left
delegating.

### `markdown-sanity` severity is split on purpose

`error` for security findings (rejected link scheme, rejected image `src`, image in a comment body,
asset-scope violation); `warning` for craft findings (unclosed fence, unmatched delimiter, dangling
backslash, malformed table).

This is load-bearing: `lint.RunAll` normalises an empty `Severity` to `error`, and `lock.Lock` refuses
on **any** error-severity finding corpus-wide. A craft finding left at the default would freeze every
lock in a consuming project because of one stray backtick in one draft.

## Non-goals, recorded as decisions

- **Reference links and footnotes** — both need a document-wide second pass and a definition namespace.
- **Raw inline HTML** — `layout: mockup` plus `raw_html_reviewed` plus the module allowlist is the
  reviewed path for HTML and should stay the only one, especially since comment bodies share the
  renderer. **Superseded by `v0.4.1` (2026-08-04):** the *layout* half of this did not hold —
  `raw_html` is now a reviewed attachment legal on any layout, not one a claim must adopt to carry
  it. `raw_html_reviewed`, the module allowlist and the lock-lifecycle leg this paragraph rests on
  are unchanged; only where the reviewed HTML may sit moved.
- **Heading-derived nav** — body headings render; the viewer's outline ignores them. One nav, one source.
- **`#` and `##`** — reserved for viewer chrome, rendered literally. `###` and deeper are headings.
- **`\<`** — leaves the backslash visible, because `<` and `&` sit outside the escapable set and are
  already HTML-escaped.

## Deferred, with reasons

| Item | Why it was deferred |
|---|---|
| `markdown.Diagnose` | The spec required a diagnostics API so the lint would not reimplement the parser. It was never built, and `internal/lint/markdown_scan.go` now carries ~1,132 lines mirroring the block scanner, inline scanner, escape set, link parser, flanking rule and table grammar. **Its own doc comment concedes the mirror can drift, and an audit found it already had.** Replacing it is larger than this release could absorb. |
| `markdown-sanity` on matched underscore runs | It reports *unmatched* runs, but `__init__` renders as bold because that run pairs perfectly — so the lint is silent on exactly the surprising case. The workaround is a backslash escape or a code span. |
| Short table rows vs the spec | The spec says a ragged row is padded and never emitted ragged. The shipped renderer emits only the cells present, because padding was the amplification vector. The engineering is right; the spec text was never amended, and the lint still describes the old rule. |
| Tarjan SCC cycle reporting | Reporting upgrade for a case a lint-clean corpus never reaches. |
| On-page cycle signal in `dossierx serve` | `check` already runs the full lint suite; only the viewer is silent. |

## Upgrading

**Locked claim bodies may render differently with no edit, no content-hash change and no ledger
event.** The approved words are identical; the rendered artifact a human approved is not.
`dossierx claim unlock` is the deliberate way to revisit them. This was a human decision: the
alternative — a migration that backslash-escaped every newly-meaningful delimiter in every locked body
— would have had `dossierx migrate` editing locked claim text, which the lock ledger exists to prevent.

Two security fixes in this release are independent of the feature work and matter to anyone on v0.3.0:
the `parseLink` bracket rescan (a denial of service live in the shipped binary) and the mockup `<img>`
gate above.
