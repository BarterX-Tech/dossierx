## Guidance diagnosis

- Guidance available at the event: `learning-to-skill` and
  `docs/MAINTAINER_SKILLS.md` cover lesson capture and consumer-bundle
  exclusion; nothing said how to draft a consumer skill ahead of its commands
  or which tests would and would not catch the gap.
- Current coverage and gap type: missing guidance, narrow. The
  invocation test's noun fallback is the fact a drafter needs and cannot see
  from a green run.
- Evidence basis: one ticket; the test source at one revision.
- Smallest useful correction: this record. No new maintainer skill: the rule
  below is one sentence, and it binds to two named tests.
- Deferred/rejected alternatives: tightening the invocation test to require
  the leaf would make every draft-ahead skill fail loudly, which is the
  honest signal, but it changes a test that guards shipped bundles and belongs
  to its own ticket with the test-audit gate applied.

## Reusable lesson

- Decision rule: when a consumer skill names a command or finding that the
  base branch does not have, list each such line in the PR (or the handback)
  by command and finding name, and do not read a green
  `TestSkills_EveryInvocationNamesARealCommand` as proof the leaf exists — it
  accepts the noun alone. Diff the skill against the real command tree on the
  first rebase that brings the commands in.
- Applies when: a `skills/<name>/SKILL.md` is written or extended against a
  spec whose engine ticket is open on another branch.
- Does not apply when: the commands the skill names are in the base branch;
  then the invocation test and the router surface test are the proof.
- Project-specific bindings: `cmd/dossierx/skills_embed_test.go`,
  `tests/skill_router_surface_test.go`, `surface.json`, `skills/embed.go`.
- Proposed remedy: none beyond the rule; see the rejected alternative above.
